# نظام تشغيل المرافق

نظام إدارة لشركات تشغيل وصيانة المرافق (O&M). واجهة عربية كاملة، وهوية الشركة
قابلة للتبديل من شاشة واحدة بلا أي تعديل على الكود.

**التقنيات:** Next.js 16 · TypeScript · Supabase · CSS متغيّرات (بلا إطار تنسيق)

---

## 🧑‍💻 ما عليكم فعله — ثلاث مهام فقط

هذه المهام تحتاج حسابات شخصية، فلا يمكن تنفيذها إلا منكم.
**(ب) قبل (ج).** و**(أ)** مستقلّة تبدأ فوراً بالتوازي.

---

### 👤 (أ) — قاعدة البيانات على Supabase

1. سجّل في [supabase.com](https://supabase.com) وأنشئ مشروعاً جديداً.
   **مشروع واحد للفريق كله**، لا مشروع لكل شخص. اختر أقرب منطقة (Frankfurt مناسبة).
2. احفظ كلمة مرور قاعدة البيانات في مكان آمن — لن تظهر مرة أخرى.
3. افتح **SQL Editor** → **New query** → الصق كامل محتوى `supabase/schema.sql` → **Run**.
4. كرّر نفس الخطوة مع `supabase/seed.sql` (بيانات تجريبية).
5. تحقّق: **Table Editor** يجب أن يُظهر 5 جداول، و `brand_settings` فيه صف واحد.
6. أنشئ مستخدمي الفريق: **Authentication → Users → Add user**
   (فعّل *Auto Confirm User* وإلا لن تستطيعوا الدخول).
7. انسخ القيمتين من **Project Settings → Data API** وأرسلهما للشخص (ج):
   - `Project URL`
   - `anon public key`

> ⚠️ **مفتاح `service_role` لا يُشارك ولا يُوضع في الكود أبداً.** هو مفتاح كامل الصلاحية.
> المطلوب فقط `anon` — وهو مصمَّم ليكون علنياً.

---

### 👤 (ب) — المستودع على GitHub

1. سجّل في [github.com](https://github.com) وأنشئ مستودعاً **خاصاً (Private)** باسم `mirafiq`.
2. فكّ ضغط ملف المشروع الذي استلمتموه، وافتح الطرفية داخل المجلد.
3. ارفع الكود:

```bash
git remote add origin https://github.com/<اسم-حسابك>/mirafiq.git
git branch -M main
git push -u origin main
```

4. أضف زميليك: **Settings → Collaborators → Add people**.

> المشروع يحتوي على سجل Git جاهز بأول commit. لا تحتاج `git init`.

---

### 👤 (ج) — النشر على Vercel

1. سجّل في [vercel.com](https://vercel.com) **بحساب GitHub**.
2. **Add New → Project** → اختر مستودع `mirafiq`.
3. قبل الضغط على Deploy، افتح **Environment Variables** وأضف القيمتين من (أ):

| الاسم | القيمة |
|------|--------|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key |

4. **Deploy**.
5. افتح الرابط الناتج، وسجّل الدخول بأحد المستخدمين الذين أنشأهم (أ).

> كل `push` على فرع `main` بعد ذلك ينشر تلقائياً خلال دقيقة.

## ✔️ شرط اكتمال التأسيس

الثلاثة يفتحون رابط Vercel من جوالاتهم، ويسجّلون الدخول، ويذهبون إلى شاشة
**«الهوية»**، ويغيّرون اللون الرئيسي ويضغطون **حفظ** — فيتغيّر النظام كله للجميع.

إذا نجح هذا، فأصعب جزء تقني في المشروع انتهى.

---

## 💻 تشغيل المشروع على جهازك

```bash
npm install
cp .env.local.example .env.local   # ثم املأ القيمتين
npm run dev                        # http://localhost:3000
```

يعمل أيضاً بلا `.env.local` — بالهوية الافتراضية وبلا تسجيل دخول.

## 📏 ثلاث قواعد لا تُخرَق

1. **ممنوع كتابة أي لون أو نصف قطر داخل أي شاشة.**
   كل شيء من المتغيّرات في `app/globals.css`.

2. **ممنوع كتابة مكوّن خاص بشاشة.**
   خذه من `components/ui.tsx`. إن لم يوجد، أضفه هناك ليستفيد منه الفريق كله.
   شاهد كل المكوّنات المتاحة في شاشة `/design`.

3. **ممنوع تعديل اسم عمود منفرداً.**
   المرجع `docs/schema.md`، والتعديل يمرّ بالثلاثة معاً.

---

## ⚠️ الفخ الأشهر في Supabase

إذا كتبت استعلاماً وعاد **فارغاً بلا رسالة خطأ** — السبب في 90% من الحالات
ليس الكود، بل **RLS** (حماية الصفوف). تحقّق أن الجدول له سياسة في
`supabase/schema.sql`، وأنك مسجّل دخول.

---

## ⏭️ الحزمة الثانية

شاشات المهام والموظفين والمواقع: عرض، إضافة، تعديل، حذف، وربطها ببعضها.
تُبنى كلها على المكوّنات الموجودة في `components/ui.tsx`.
